# 当前两个Judge与Reward的工程判断

## DeepSeek训练Judge

我的判断是：当前deepseek-flash、thinking disabled、T=1这套配置的监督可靠性
不够，训练标注应优先校准和升级。最终v4已经解决结构化输出和方向解析，继续
修格式或增加重试不会解决偏好质量。

四组选择展示首位回答的比例约58.7%–63.8%；244条双向观察边内的换序差约
24.19个百分点，重复判断也存在明显不一致。平衡flip可缓解固定候选的平均方向
偏差，但仍留下单条标签噪声。近似平局被强制二选一也会增加不稳定性。
这些证据足以把标注质量列为首要工程问题；24.19%不是人类语义错误率。

下一轮应在代表性的独立开发样本上比较更强判断配置，结合换序、重复一致性和
少量人工核对后固定统一标注协议。单纯降温可能把错误固定，不能代替质量校准。

## Luna评价Judge

我的判断是：当前Luna可继续作一致的评价基线，尚没有证据支持推翻全部既有
评价；但当前配置和样本量不足以精确区分一两个百分点的收益。

同一回答在两个顺序上均正确判平，原始方向和AB/BA统计无错误。小批更强模型
复核没有显示系统性失效；但原AB/BA不一致约16%–24%，因此后续应对关键差异
增加代表性强模型/人工抽查。原40对参考刻意富集分歧，不用它推算总体准确率。
PRISM与Empirical约39%–40%的评价回答逐字相同，也确实限制了可观测差异。

## 用户提出的三个原因

我认同Reward是当前的主要嫌疑，优先级为标注质量、有效覆盖/预算，再用独立
泛化验证判断改善是否成立。泛化弱是观测结果；标注噪声和有限覆盖是原因候选，
还可能与冻结特征表示、正则共同作用。

Reward优化器已经把当前L2 BT目标拟合到位：四个梯度无穷范数均低于1e-6，
PRISM训练一致率也接近重复冲突标签给出的经验上限。增加Reward优化迭代无助于
解决这些统计问题。现有交叉留出一致率约55%–60%，logloss1.21–1.24高于
常数0.5预测的0.693，显示对留出标签的泛化/校准偏弱。

我认为1024对当前任务偏紧，尤其PRISM实际只覆盖约242/243个prompt和266/269条
不同边。这个判断应通过同Judge的1024/2048/4096 Reward级预算曲线检验；
不按2048参数和1024标签的维数比较直接下结论。重复观察可以减小标注方差，
增加预算时应同时观察覆盖和开发集收益。

数值修复后的固定候选敏感性检查发现，具体q对精度敏感，但集中程度仍相近：
前1%边承载88.59%概率，1024次期望约269条不同边、242个prompt。因此后续要在
一致数值协议下重建Design，再检验标签质量和预算，见[数值修复](numerical-protocol.md)。

PPO在原500题上也没有稳定提高自己的冻结Reward，且已定位数值问题，因此先
修复数值链路，沿用旧Reward做短程验证，有助于把PPO因素从Reward判断中分离。
随后分别比较Judge质量和标签预算，再统一训练两种sampling对应的策略。
本轮不改Sampling目标、强凸BT估计器或原最终结果。
