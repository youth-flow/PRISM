# V2 Empirical：Reward 与 PPO 定位诊断（2026-11-17）

用户要求先独立检查 Empirical 为什么没有明显超过 SFT。本次只检查原四个 Empirical Reward/策略，未改变正式结果，未训练新头或策略，未生成新回答，未调用 API。

结论：实测发现 Reward 的泛化差距和过度自信；四个 PPO 策略在原 500 留出 prompts 上也没有显示自身 Reward 的正增益。已定位到两层性能缺口，尚未发现新的反号、断梯度或保存错策略的实现错误。critic/GAE 与奖励定标的组合是应优先做因果对照的机制，当前证据不能唯一归因。

## 1. Reward 学到了信号，但泛化和概率校准不足

固定已训练权重，用另一 seed 的原 Empirical4096 标签验证；剔除被测 seed 的 4096 训练集中出现过的全部 prompt。同一 seed 的 2048/4096 头使用完全相同的留出标签，避免预算间测试题不同。seed11 对应 1045 条/567 prompts，seed23 对应 992 条/555 prompts。标签未参与被测 Reward 拟合；无标签候选曾用于 Design，因此这是 prompt 隔离的事后诊断，不是新独立 benchmark，标签也不是人类真值。

| 预算 / seed | 训练准确率 | 留出准确率 | 留出 BT logloss | 留出准确率 95% prompt bootstrap |
|---|---:|---:|---:|---|
| 2048 / 11 | 91.02% | 63.92% | 0.889 | [60.71%, 67.09%] |
| 2048 / 23 | 90.33% | 62.60% | 0.886 | [59.31%, 65.73%] |
| 4096 / 11 | 84.22% | 64.78% | 0.744 | [61.56%, 68.06%] |
| 4096 / 23 | 83.56% | 63.71% | 0.721 | [60.52%, 66.91%] |

模型有排序信息：留出准确率高于约 50% 的多数类基线。但 2048 档从训练约 90%–91% 降至留出约 63%，4096 仍有约 19–20 个百分点差距。2048 的留出 logloss 约 0.89，95% 区间下界约 0.79，均高于恒定预测 0.5 的 log(2)=0.693。4096 的点估计 0.721–0.744 仍偏高，但其区间包含 0.693，不能说已显著差于常数概率预测；其 Brier 0.234–0.237 优于 0.25，说明保留了有效信号。

把高置信度样本（预测所选答案概率超过 90%）合并后，2048 两个模型平均自信约 96.8%–97.0%，实际准确率约 74.2%–74.6%；4096 平均自信约 96.3%–96.6%，实际约 78.4%–80.3%。这是本批留出标签上的具体校准缺口。

原目标和梯度被重新构造并与训练 report 匹配，梯度无穷范数通过阈值。因此这里的已确认问题是统计泛化/校准，不能把它说成 L-BFGS 没求解成功。冻结 EOS 线性特征的表达限制、有限数据与固定正则造成的方差/偏差，以及标注噪声，都可能参与；没有消融不能分配各自责任。

经验训练记录另显示：约 8.7%–9.5% 的比较文本逐字相同，二元协议仍必须选一；重复边判断成对不一致约 9.3%–14.2%。它们不是人类错误率，也不足以单独解释全部泛化差距。

## 2. PPO 没有在留出题上兑现自身奖励提升

独立加载冻结 FP32 SFT backbone，给原有 SFT 与四策略共 2500 条已有回答打分；缓存去重后仅 1444 次 backbone 前向，没有重采样。自然 EOS 与截断后补特征 EOS 都与真实 PPO FrozenReward 适配器比对，最大误差 1.994e-6。对每个头，比较其自身策略回答与同 prompt 的原 SFT 回答。

| Reward / 对应策略 | SFT 平均 Reward | 策略平均 Reward | 配对差：策略减 SFT | 95% prompt bootstrap 区间 |
|---|---:|---:|---:|---|
| 2048 / 11 | 2.610 | 2.479 | -0.130 | [-0.449, +0.206] |
| 2048 / 23 | 10.379 | 10.358 | -0.021 | [-0.346, +0.283] |
| 4096 / 11 | 2.074 | 2.033 | -0.041 | [-0.269, +0.184] |
| 4096 / 23 | 6.284 | 6.225 | -0.059 | [-0.286, +0.153] |

四个点估计均略负、区间全部包含 0，因此没有稳定的自身 Reward 提升，也不能宣称已显著下降。这一步不依赖新 Judge 判断；外部 Judge 的打分差异不能单独解释它。不同 Reward 的零点和尺度不同，不能跨行按分数绝对值给模型排序。

在原 Sol 对这些政策回答与 SFT 回答的 AB/BA 同向、非平局子集上，各 Reward 与 Sol 的方向一致率约 59.4%–65.4%，再次说明对实际策略回答的奖励排序也并不十分可靠。此项为原最终测试集上的事后诊断，不用于选参。

本表测的是留出 500 prompts，仍不能严格区分“训练 prompts 上没优化好”和“训练上有改善、留出策略未泛化”。训练日志前八轮/后八轮平均 Reward 也未一致上升，但批次不同，不能替代固定训练探针的学习曲线。下一轮必须同时保存固定训练探针与独立开发探针。

## 3. 最值得验证的机制：未定标终点奖励、弱初始 critic 与 GAE

当前代码事实：Reward 使用原始 w^T phi，不做固定参考分布的中心化/定标；critic 是冻结 SFT 加 2049 参数线性头，权重/bias 全零初始化；gamma=1、lambda=0.95、终点奖励；actor/critic 初始 LR=1e-5/3e-5，均在 64 轮内线性衰减。actor 在 critic 尚未学好时即开始更新；末轮 actor LR 为 1.5625e-7。

原 SFT 回答在四个 Reward 下均值分别为 2.610、10.379、2.074、6.284，critic 则都从 0 开始。BT 主要约束同 prompt 的分数差，并不替 PPO 自动确定恰当的奖励基准与尺度。这个零点差本身不是偏好模型错误；在精确回报和正确基线下，给所有完整回答加常数不会改变 gamma=1 的最优策略。

但当 critic 仍接近 0、忽略 KL 项时，距离终点 k 步的终点奖励在 GAE 中的直接系数为 lambda^k。lambda=0.95 时，50/100/200 步分别约 0.077/0.00592/0.000035。一个原本不区分回答质量的常数终点偏移也会形成不同时间位置的优势形状；全局 advantage 白化不会自动消除这种时间结构。随着 critic 变准，bootstrap 可以补偿，不能把这个零 critic 推导当作最终 V2 优势信号的实际测量。

所以，长回答、稀疏终点奖励、未经中心化的正偏分数、初始弱 critic，再加较快学习率衰减，可能让 actor 的有效学习信号偏弱或偏向末端。当前是基于代码与数据的机制假设，尚无 V2 critic explained variance、实际优势时序或单因素对照，不能直接宣布 critic 或 lambda 是唯一根因。GAE 的价值误差与偏差/方差权衡见[原论文](https://arxiv.org/abs/1506.02438)。

不能直接把 lambda 改 1 当作已证明的修复：此前短程 D/E 对照使用另一 Reward 与更高 actor LR，lambda1 未表现更好，不能代替当前设置下的诊断。奖励缩放也会改变相对于固定 KL 系数的有效优化强度，需要显式记录；概率温度校准本身不会修正奖励排序错误。

## 4. 当前证据不支持的归因

- “根本没更新”：四组实际 256 个 actor/critic AdamW 步、FP32 LoRA 更新与概率一致性验收通过。
- “旧 BF16 数值误差还在主导”：本轮全链路 FP32，更新前路径闸门持续通过；旧错误尝试未混入当前策略。
- “clip 把 actor/critic 卡死”：actor 平均 clip fraction 仅约 0.0023%–0.0072%，四组 value clip fraction 全程为 0。
- “critic 经全局范数裁剪压制 actor”：正常训练循环没有执行该范数裁剪，且两者可训练参数独立。
- “把 PPO loss 降下去就一定更好”：固定开发自身 Reward 的提升及外部偏好仍需验证，不能靠 loss 或步数代替。

## 5. 修复顺序建议（本次未执行）

1. Reward 保持冻结 backbone＋线性头，用共用、按 prompt 隔离的开发集选择正则并评估排序/校准。先比较 L2 与概率校准，不直接重花钱扩大标注；温度校准可修正置信度但不会改变排序。最终 500 题不得反过来当开发集。
2. 固定同一已训练 Reward，做小规模因果对照，优先检验参考分布中心化、critic 预拟合/初始化及其组合；记录 critic explained variance、return/value 误差、有效 token 优势随位置的分布和 actor 梯度。中心化/缩放要分开，缩放时显式控制与 KL 的相对尺度。
3. 固定训练探针与独立开发探针都应显示自身 Reward 正向改善后，再看外部偏好；达到这些性能验收后再跑完整多单元。学习率或 episodes 的调整放在具体机制检查之后。

前面汇报较充分地证明了“数值求解成功、真实更新完成”，没有及时补齐以上两项性能诊断。这是实验验证流程的缺口：机械验收通过，仍不能称 Reward 与 PPO 的学习效果已达到预期。
