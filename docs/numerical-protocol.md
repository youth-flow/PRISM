## 实现

runtime.numerics=fp32_consistent_v1要求runtime.dtype=float32。模型骨干、adapter、
value head使用FP32，关闭TF32；候选、序列logp、PPO及评价因此采用同一精度基准。
selected_logprobs统一使用FP32 log-softmax，保留autograd，按响应行控制临时内存。

PPO扩展固定于TRL0.15.2。每轮生成完成、参数更新之前，取前4条真实rollout，
按实际训练microbatch重算full-forward logp，与实际生成分布保存的old_logp比较。
只在有效action位置检查：max abs logp error<=1e-3，approxKL<=1e-7；这两个数值
是本协议的工程验收阈值，不是研究优化收敛阈值。失败会阻止本轮optimizer更新。
该检查不消费CPU/CUDA随机数，reference logp也必须为FP32。

扩展同时在生成logits使用结束后释放大张量，并使approxKL、ratio、entropy诊断
按有效token统计。AST测试移除这些明确修改后，train方法与固定上游完全一致；
PPO目标、GAE、采样温度、batch、学习率和步数日程均保留。未在本步更改critic
学习率或加入梯度范数裁剪，报告仍明确标记该裁剪未执行。

上游代码来源与改动已注明，Apache2.0许可和归属位于LICENSES/。

## 全链路精度敏感性

已对原12000条固定候选重新计算FP32特征/logp，四个独立单卡作业为1980529–32。
它们保留原token，属于敏感性分析，不冒称重新按FP32策略生成了候选池。
后续正式新版需要按新配置重新生成相应依赖。

四组各500条原评价回答的FP32重打分由1980535完成：

| 单元 | 原序列log-ratio均值 | FP32在同一批旧token上的均值 |
| --- | ---: | ---: |
| Empirical11 | 0.002366 | -0.002112 |
| Empirical23 | 0.019454 | -0.001950 |
| PRISM11 | 0.009678 | -0.002476 |
| PRISM23 | -0.002606 | -0.004216 |

原均值对精度敏感，不能据原微小KL差别给方法排序。右列使用BF16旧策略生成的
回答，不是新FP32策略分布下的无偏MC KL，不替换原冻结主指标。负值也不裁成0。

候选BF16复核另用1980539重新按原dtype加载模型。47例中35例（原4090分片）
特征和logp逐元素完全一致；12例非零差异均来自原A100分片，说明原混合硬件的
低精度结果存在差异。原q在A100分片的质量约25.05%，对应边数约21.73%，
不据此断言集中分布由硬件导致。四个pool任务附带的FP32模型直接downcast spotcheck
还会转换RoPE浮点buffer，不将它冒称为原BF16加载的严格复现；正确基准以1980539为准。

新近优q为0.725407；两者是在同一个新几何上的比较。不同精度的最优目标值
不直接用来比较策略质量。

此前将“b/K公式实现正确”概括成“K没有问题”过宽：数值稳定性当时未验全。
本次表明上游几何和具体选点对精度高度敏感，不能沿用旧q来启动新协议。
原Design证书仍对应原输入，新版正式候选/几何/查询应按统一协议重建。

集中程度没有因此消失：新q前1%边承载88.5932%概率，逆集中度156.61，
1024次有放回抽样期望269.06条不同边、242.09个prompt；原q期望约270.45条边。
因此不能把PRISM集中全部归为BF16，标签质量和有限覆盖问题继续独立验证。
